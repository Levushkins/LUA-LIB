Всё о Lua скриптинге для MoonLoader

Это руководство призвано исполнить две цели: обучить разработке скриптов с нуля и восполнить все пробелы в знаниях о Lua скриптинге под MoonLoader. В нём освещены все аспекты разработки - от самого простого до продвинутых возможностей и приемов, то есть оно подходит как и для начинающих скриптеров, так и для программистов с опытом.

Установка MoonLoader

Перед продолжением необходимо установить сам MoonLoader, желательно через программу установки и с дополнительными инструментами:
1. Скачайте установщик MoonLoader последней версии и запустите, следуйте шагам программы установки
2. На странице выбора компонентов отметьте нужные скрипты (рекомендуется выбрать все)
AutoReboot - позволяет автоматизировать перезагрузку ваших скриптов при их редактировании не выходя из игры. Особенностью данного скрипта является то, что он не загружает новые добавленные скрипты из папки moonloader самостоятельно.
Reload All - позволяет перезагружать абсолютно все скрипты в папке moonloader, включая добавленные после запуска игры. Для перезагрузки нажмите сочетание клавиш Ctrl + R.
SF Integration - упрощает отслеживание состояния скриптов путём вывода сообщений отладки, ошибок и другой информации в консоль SAMPFUNCS. По сути дублирует сообщения из moonloader.log в консоль.
3. Если вы намерены делать скрипты для SA:MP, выберите SAMP.Lua и отдельно установите SAMPFUNCS
4. Это не обязательно, но не помешает установить и MoonAdditions - эту библиотеку используют некоторые скрипты и она неплохо расширяет стандартные возможности скриптинга
5. Выберите установку расширения для Notepad++, если вы будете использовать программу Notepad++ для редактирования Lua скриптов

Среда разработки

Для работы с Lua достаточно любого текстового редактора, но какой-нибудь блокнот Windows для этого подходит совсем плохо, поэтому лучше использовать специализированные программы. На текущий момент полная поддержка MoonLoader есть в Atom и Notepad++, помимо этого есть пользовательские дополнения для Visual Studio Code и Sublime Text.

Atom
Для начала работы с Lua нужно установить сам Atom. После установки Atom обязательно установить пакет для удобства редактирования скриптов. Нажимаем Ctrl + , и переходим во вкладку Install, в поле поиска вводим "moonloader" и устанавливаем первый в списке пакет.
Проект по-умолчанию: В меню File выбираем пункт Open Folder... и указываем путь до папки moonloader, после этого она откроется как проект.
Кодировка по-умолчанию: Для установки кодировки по-умолчанию при создании нового скрипта переходим в настройки всё тем же сочетанием Ctrl + , и выбираем пункт Core. В поле File Encoding выбираем Cyrillic (Windows-1251).

Notepad++
Проект по-умолчанию: В меню "Файл" выбираем пункт "Открыть Папку как Проект" и указываем путь к папке "moonloader".
Кодировка по-умолчанию: Над лентой выбираем пункт Опции и переходим в Настройки. В меню слева выбираем пункт Новый документ и в разделе кодировки ставим флажок на список, в котором выбираем кодировку Windows-1251.

Программирование

Lua скрипты и логи
Для начала нужно создать сам скрипт - он из себя представляет обычный текстовый файл с расширением .lua. Поместить его необходимо в папку moonloader, находящуюся в папке игры. Из корня этой папки MoonLoader загружает все скрипты с расширениями .lua и .luac (скомпилированные).
В этой же папке создаётся файл moonloader.log, в который ведётся журналирование всех важных событий, происходящих со скриптами: загрузка, завершение, сообщения скриптов и самое главное - ошибки.

Глобальная область
Глобальная область - это основное тело скрипта, т.е. всё, что находится вне функций. Код из неё выполняется один раз после загрузки скрипта и не может быть приостановлен.

Пример:
local vkeys = require 'vkeys'
local myName = "Alexander"

function main()
-- В данном примере никаких действий с main нет, поэтому тут его можно не объявлять. Скрипт выполнит глобальную область и завершит работу.
end

main - основной поток любого скрипта для MoonLoader. Вызывается один раз после чего скрипт завершает свою работу и выгружается, если в нём нет активных потоков и зарегистрированных событий. Для того, чтобы скрипт продолжал работать, необходимо удерживать поток активным (бесконечная задержка или бесконечный цикл).

Пример:
function main()
  print("Hello World!")
  while true do -- Объявляем бесконечный цикл
    wait(1000) -- Ждём секунду, 1000 ms = 1 s
    print("I'm alive!")
  end
end

Задержки и потоки
В ML для осуществления задержек используется функция wait(int time):
-1 - устанавливает непрерывное ожидание, использование допустимо только в main
0 - задержка на один кадр
остальные значения указывают задержку в миллисекундах

Использование задержек недопустимо в callback-функциях. Для создания задержки в такой функции используйте создание потока:
function callback()
  lua_thread.create(function ()
    doFade(1000, true)
    wait(3000) -- на 3 секунды гасим экран
    doFade(1000, false)
  end)
end

Потоки (lua_thread.create) служат для выноса определенных действий за рамки основного потока, а так же для создания задержек выполняемого кода там, где это невозможно реализовать стандартными методами.

Директивы
Директивы принято обозначать в самом начале скрипта.

Пример:
script_name("A complete guide to MoonLoader")
script_authors("DonHomka", "FYP")
script_version("0.1.0-beta")
script_description[[
- Пример использования директив
- Вывод информации в лог
]]

События и колбэки
Обработчики событий могут иметь входящие и возвращаемые параметры. Зарегистрировать обработчик можно либо функцией с соответствующим именем, либо через addEventHandler.
Внутри обработчиков событий нельзя использовать задержки.

Пример:
function onScriptTerminate(script, quitGame)
  if script == thisScript() then
    print("bye world")
  end
end

Колбэки (функции обратного вызова) связаны с конкретной сущностью (командой, идентификатором и т.п.). Пример: downloadUrlToFile.

Использование библиотек
Все модули располагаются в директории moonloader/lib/. Подключение осуществляется при помощи функции require 'название'.

Никогда не публикуйте свои работы вместе со стандартными библиотеками или с изменениями в сторонних библиотеках - это может привести к проблемам у пользователей.

Рекомендации
- Добавляйте информацию о скрипте при помощи директив
- Соблюдайте единый стиль кода и табуляцию
- Называйте переменные и функции внятными именами
- Вместо предопределенных переменных playerPed и playerHandle стоит использовать PLAYER_PED и PLAYER_HANDLE соответственно.
- vkeys - стандартный модуль, хранящий все ID и имена виртуальных клавиш. Коды клавиш были перенесены в отдельный модуль. Использование констант из модуля moonloader считается устаревшим.

Компиляция скриптов
Для компиляции Lua скриптов под MoonLoader v.026 и выше скачайте интерпретатор LuaJIT v2.1.0-beta3, распакуйте архив и перетаскивайте lua-файл на compile.bat.

Создание модулей
В модуле все переменные должны быть локальными. Глобальные переменные назначаются только в особых случаях.

Пример модуля (example.lua):
local mod = {}
mod._VERSION = '1.0.0'
function mod.showTextFormatted(msg, duration, ...)
  printStringNow(string.format(msg, ...), duration)
end
return mod

Использование:
local example = require 'example'
function main()
  example.showTextFormatted('My module version is %s', 1000, example._VERSION)
end

Импорт и экспорт
Система экспорта позволяет разделить общие данные между скриптами. Скрипт назначает глобальную таблицу EXPORTS, другие скрипты получают доступ через import.

Экспортирующий скрипт (status_notification.lua):
function EXPORTS.notify(msg, color)
  -- код функции
end

Использование в другом скрипте:
local notification = import 'status_notification'
function main()
  notification.notify('Hello!')
end

У импортированных функций есть особенность: вместо копирования для них создаётся интерфейс, позволяющий вызывать функцию так, как будто она была вызвана в экспортирующем скрипте.

Технические уточнения из обсуждения:

Вопрос: Чем playerPed отличается от PLAYER_PED?
Ответ: Ничем. Меняются стандарты. playerPed - устаревшее написание константы, PLAYER_PED - более верно.

Вопрос: Есть ли что-то на подобии пакета moonloader только для sublime text?
Ответ: autocomplete for sublime (ссылка на blast.hk/threads/19457/).

Замечание по VS Code: VScode хорош, но не имеет "нормального" набора разработчика из коробки, как у Atom. Настройка требует дополнительных действий.

Исправление ошибки в примере кода vkeys:
В строке:
print(vkeys.VK_RSHIFT, vkeys.id_to_name(views.VK_RSHIFT))
Нужно заменить 'views' на 'vkeys'. Правильно:
print(vkeys.VK_RSHIFT, vkeys.id_to_name(vkeys.VK_RSHIFT))
