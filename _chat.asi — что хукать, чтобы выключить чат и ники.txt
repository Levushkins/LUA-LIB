_chat.asi — что хукать, чтобы выключить его, не удаляя файл
===========================================================

Разбор конкретной сборки: PE32 DLL, ImageBase 0x10000000, TimeDateStamp 0x6A7A4372,
SizeOfImage 0x1C7000, pdb-путь "C:\dev\imgui-chat\build\Release\_chat.pdb".
Внутри: Dear ImGui + freetype (свой рендер шрифтов), эмодзи, json 3.11.3,
MAX_PLAYERS 0x800, обращения к libcef.asi (IsCefMenuActive), AZVoice.asi
(IsPlayerSpeaking), libPED (findPed).

ВАЖНО: все RVA ниже — из этой сборки. После обновления лаунчера они уедут,
поэтому в скрипте стоит проверка TimeDateStamp + сигнатуры первых байт.


1. Что мод делает с samp.dll
----------------------------
При старте он берёт GetModuleHandleW(L"samp.dll") и ставит инлайн-джампы (E9)
прямо в начало функций (оригинальные байты НЕ сохраняются, трамплинов нет):

  samp+0x011C0 -> _chat+0x46530   создание/обновление неймтега игрока
  samp+0x012D0 -> _chat+0x46570   удаление неймтега
  samp+0x0EC50 -> _chat+0x446D0
  samp+0x0F3D0 -> _chat+0x44980
  samp+0x0F580 -> _chat+0x44B50
  samp+0x666A0 -> _chat+0x463E0   CChat::AddEntry — приём строки в чат (5 арг., ret 0x14)
  samp+0x66A72 -> _chat+0x46590   середина функции: старт ImGui-кадра (NewFrame)
  samp+0x67460 -> _chat+0x464D0
  samp+0x67680 -> _chat+0x464F0   CChat::Draw -> jmp на главный рендер _chat+0x13C40
  samp+0x68D10 -> _chat+0x46510
  samp+0x68E10 -> _chat+0x46500
  samp+0x69260 -> _chat+0x46520

Плюс хуки через MinHook-подобный движок (уже с трамплинами):

  samp+0x13CB0 -> _chat+0x46600  (трамплин в _chat+0x17902C)
  samp+0x13E80 -> _chat+0x465A0  (_chat+0x179028)
  samp+0x15A50 -> _chat+0x46630  (_chat+0x179030)
  samp+0x40150 -> _chat+0x46650  (_chat+0x179034)
  samp+0x60EE0 -> _chat+0x467B0  (_chat+0x179024)

Плюс просто заглушенные функции самп (в первый байт пишется C3):
  samp+0x01340, 0x66760, 0x671C0, 0x67A50, 0x73B20, 0x74C30
и два патча джампов: samp+0x73B34 <- E9 3D 02 00 00 90, samp+0x74C44 <- E9 5E 02 00 00 90.

Отсюда два следствия:
  * родной чат SA-MP уже уничтожен (первые байты его функций затёрты), просто
    "выключить" мод и получить обратно стандартный чат нельзя — для этого надо
    восстанавливать оригинальные байты samp.dll из чистого файла на диске;
  * ImGui-кадр НАЧИНАЕТСЯ в хуке samp+0x66A72, а заканчивается и рисуется в
    главном рендере (_chat+0x13C40). Поэтому глушить целиком _chat+0x464F0 /
    _chat+0x13C40 нельзя: NewFrame будет вызываться, а Render — нет.
    Надо глушить не весь рендер, а конкретные функции внутри него.


2. Штатный API — ники
---------------------
Мод сам экспортирует переключатель (это самый безопасный путь):

  IsCustomNameTagEnabled   rva 0x186E0   bool __cdecl (void)
  SetCustomNameTagState    rva 0x186F0   void __cdecl (bool)
  toggle_nametags          rva 0x186F0   тот же адрес, второе имя
  api                      rva 0x18700   возвращает указатель на объект мода
  _push_item_slot@8        rva 0x405C0

Флаг лежит по адресу [[_chat+0xE5000] + 3]; SetCustomNameTagState пишет его и
дополнительно прогоняет весь пул неймтегов, переключая им стиль (1 <-> 3).
То есть это переключение "кастомные ники <-> классические", а не полное
выключение отрисовки. Полное выключение — пункт 3.

  local ffi = require 'ffi'
  local p = getModuleProcAddress('_chat.asi', 'SetCustomNameTagState')
  ffi.cast('void (__cdecl*)(bool)', p)(false)


3. Что патчить, чтобы выключать по-настоящему
---------------------------------------------
Все четыре функции ничего не возвращают, поэтому глушатся записью ret в первый
байт, а включаются записью сохранённых оригинальных байт обратно:

  rva 0x11B20  окно чата + поле ввода     55 8B EC 83 EC 3C   -> C3
               (рисует ImGui-окна "###chat" и "###input", вызывается один раз
               из главного рендера по адресу _chat+0x14892)

  rva 0x35760  отрисовка ников            55 8B EC 6A FF 68   -> C3
               (__thiscall, ecx = _chat+0xEB970; проход по пулу неймтегов,
               внутри и проверка флага кастомных ников)

  rva 0x12710  окно настроек чата         55 8B EC 83 EC 0C   -> C3
               (ImGui-окно "###CCFG")

  rva 0x463E0  приём сообщений в буфер    55 8B EC 6A FF 68   -> C2 14 00
               (детур CChat::AddEntry; ret 0x14 обязателен — 5 аргументов
               чистит вызываемая сторона. Нужен, только если хочется, чтобы
               мод вообще не копил историю; для простого "скрыть" не нужен)

Что при этом остаётся: ImGui-кадр по-прежнему корректно открывается и
закрывается, скриншоты/эмодзи/прочая логика мода живы, крашей нет.
Что ломается: пока окно чата выключено, вся переписка невидима, в том числе
sampAddChatMessage из других скриптов — родной чат SA-MP затёрт хуками (см. п.1),
так что ввод текста идёт вслепую. Держать выключенным имеет смысл, только если
вместо него работает свой чат/рендер.

Полезные адреса про запас (на случай другой задачи):
  rva 0x13C40  главный рендер (тело хука CChat::Draw)
  rva 0x464F0  стаб CChat::Draw: E9 4B D7 FC FF (jmp 0x13C40)
  rva 0x32E00  создание/обновление неймтега игрока (ret 0x20, __thiscall)
  rva 0x46530  стаб хука samp+0x11C0 (ret 0x28, возвращает playerid в ax)


4. Как вернуть родной чат SA-MP
--------------------------------
Оригинальные байты самп мод не сохраняет, поэтому "отхукать" из памяти нечего.
Единственный корректный способ — прочитать чистый samp.dll с диска, перевести
RVA из таблицы п.1 в файловое смещение по заголовкам PE и записать по 5 байт
(и по 1 байту для C3-заглушек) обратно в память. Делать это надо один раз при
старте, до того как мод начнёт рисовать, иначе часть состояния уже разъедется.


5. Готовый скрипт
-----------------
chat_asi_switch.lua в этом же репозитории: проверяет TimeDateStamp и сигнатуры,
сохраняет оригинальные байты, снимает патчи при выгрузке.

  /casw chat    — окно чата + ввод
  /casw nick    — ники над игроками
  /casw cfg     — окно настроек
  /casw feed    — приём сообщений в буфер
  /casw style   — кастомный/классический стиль ников (через экспорт мода)
  /casw all     — чат и ники разом
  /casw on      — снять все патчи
  /casw status  — что сейчас включено

Учти: это правка памяти клиентского мода лаунчера, античит сервера в принципе
может её увидеть.
