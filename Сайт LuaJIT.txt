Эта документация предназначена для LuaJIT 2.1.

LuaJIT полностью совместим "снизу вверх" с Lua 5.1. Он поддерживает все стандартные функции библиотеки Lua и полный набор функций Lua/C API. LuaJIT также полностью совместим на уровне ABI с Lua 5.1 на уровне компоновщика/динамического загрузчика. Это означает, что вы можете скомпилировать C-модуль с использованием стандартных заголовков Lua и загрузить ту же общую библиотеку как из Lua, так и из LuaJIT.

Расширения и модули

LuaJIT поставляется с несколькими встроенными модулями расширения:

bit.* — Битовые операции
LuaJIT поддерживает все битовые операции, определенные в Lua BitOp:
bit.tobit, bit.tohex, bit.bnot, bit.band, bit.bor, bit.bxor, bit.lshift, bit.rshift, bit.arshift, bit.rol, bit.ror, bit.bswap.
Этот модуль является встроенным — вам не нужно скачивать или устанавливать Lua BitOp. FFI добавляет поддержку 64-битных битовых операций, используя те же функции API.
Пример использования:
local bit = require('bit')

ffi.* — Библиотека FFI
Библиотека FFI позволяет вызывать внешние C-функции и использовать структуры данных C из чистого кода Lua.

jit.* — Управление JIT-компилятором
Функции в этом модуле управляют поведением движка JIT-компилятора.

Расширения C API
LuaJIT добавляет некоторые дополнительные функции в Lua/C API.

Профайлер
LuaJIT имеет встроенный профайлер.

Улучшенные функции стандартной библиотеки

xpcall(f, err [,args...]) передает аргументы
В отличие от стандартной реализации в Lua 5.1, xpcall() передает любые аргументы после функции ошибки в вызываемую функцию.

load*() обрабатывают исходный код в UTF-8
Символы, не входящие в ASCII, прозрачно обрабатываются парсером Lua. Это позволяет использовать UTF-8 символы в идентификаторах и строках. UTF-8 BOM в начале исходного кода игнорируется.

load*() добавляют параметр mode
Как и в Lua 5.2, функции loadstring(), loadfile() и load() добавляют необязательный параметр mode.
Значение по умолчанию — 'bt' (разрешает и исходный код, и байткод). 't' — только текст, 'b' — только байткод.
Добавление 'W' в строку режима принудительно устанавливает 32-битный формат байткода, 'X' — 64-битный (для кросс-компиляции).

tostring() и другие канонизируют NaN и ±Inf
Все преобразования чисел в строки единообразно преобразуют нефинитные числа на всех платформах: NaN в 'nan', положительную бесконечность в 'inf', отрицательную в '-inf'.

tonumber() и другие используют встроенное преобразование строк в числа
Преобразование не использует strtod(), что избегает проблем с реализациями библиотек C. Поддерживает полную точность IEEE-754, работает независимо от локали и поддерживает шестнадцатеричные числа с плавающей запятой (например, 0x1.5p-3).

string.dump(f [,mode]) генерирует переносимый байткод
Добавлен дополнительный аргумент. Если установлено true или строка, содержащая символ 's', генерируется "очищенный" (stripped) байткод без отладочной информации.
Байткод переносим между архитектурами внутри одной мажорной+минорной версии LuaJIT. Байткод из Lua 5.1 несовместим.
Добавление 'd' в параметр mode делает дамп детерминированным (одинаковый исходный код всегда дает идентичный байткод).

table.new(narray, nhash) выделяет таблицу заранее заданного размера
Доступна через require('table.new'). Полезно для больших таблиц, если итоговый размер известен заранее.

table.clear(tab) очищает таблицу
Доступна через require('table.clear'). Удаляет все ключи и значения, но сохраняет выделенные размеры массива/хэша.

Улучшенный PRNG для math.random()
LuaJIT использует Tausworthe PRNG с периодом 2^223. Качество результатов выше, чем у стандартного ANSI rand(). math.randomseed() без аргументов использует системную энтропию.

io.* функции поддерживают 64-битные смещения файлов
Можно открывать файлы размером более 2 ГБ и использовать fp:seek() для работы с ними.

VM с полной поддержкой возобновления (Fully Resumable VM)
Вы можете делать yield из корутины даже через контексты, где это невозможно в Lua 5.1: через pcall() и xpcall(), через итераторы и метаметоды.

Расширения из Lua 5.2
- goto и метки ::label::.
- Hex-экранирование '\x3F' и '\z' в строках.
- load(string|reader [, chunkname [,mode [,env]]]).
- math.log(x [,base]).
- string.rep(s, n [,sep]).
- string.format(): %q обратимо, %s проверяет __tostring.
- Шаблон соответствия строк %g.
- io.read('*L').
- package.searchpath().

Опциональные функции (при сборке с -DLUAJIT_ENABLE_LUA52COMPAT):
- goto становится ключевым словом.
- break можно ставить в любом месте.
- pairs() и ipairs() проверяют __pairs и __ipairs.
- table.pack() и table.unpack().

Расширения из Lua 5.3
- Unicode escape '\u{XX...}' в строковых литералах.
- Таблица аргументов arg может быть прочитана/изменена в LUA_INIT и -e чанках.
- io.read() и file:read() принимают форматы с ведущей * или без неё.
- assert() принимает любой тип объекта ошибки.
- table.move().
- coroutine.isyieldable().

Взаимодействие с исключениями C++
LuaJIT поддерживает перехват C++ исключений через pcall() на поддерживаемых платформах (GCC, Clang, MSVC).

Библиотека FFI

FFI (Foreign Function Interface) позволяет вызывать внешние C-функции и использовать структуры данных C напрямую.

Пример вызова внешней функции:
local ffi = require('ffi')
ffi.cdef[[
int printf(const char *fmt, ...);
]]
ffi.C.printf('Hello %s!', 'world')

Использование структур данных C:
local ffi = require('ffi')
ffi.cdef[[
typedef struct { uint8_t red, green, blue, alpha; } rgba_pixel;
]]
local function image_ramp_green(n)
  local img = ffi.new('rgba_pixel[?]', n)
  local f = 255/(n-1)
  for i=0,n-1 do
    img[i].green = i*f
    img[i].alpha = 255
  end
  return img
end

Преимущества FFI:
- Потребление памяти для структур в разы ниже, чем у таблиц Lua.
- Производительность на уровне нативного C кода.
- Код JIT-компилятора может инлайнить вызовы C-функций.

Основные функции API FFI:
- ffi.cdef(def): Добавляет C-декларации типов и функций.
- ffi.C: Пространство имен по умолчанию для стандартных библиотек C.
- clib = ffi.load(name [,global]): Загружает динамическую библиотеку.
- cdata = ffi.new(ct [,nelem] [,init...]): Создает cdata объект заданного типа.
- ctype = ffi.typeof(ct): Создает ctype объект (конструктор).
- cdata = ffi.cast(ct, init): Приведение типов.
- ctype = ffi.metatype(ct, metatable): Ассоциирует метатаблицу с типом C (struct/union).
- cdata = ffi.gc(cdata, finalizer): Назначает финализатор (деструктор) для cdata объекта.

Справочник по семантике FFI:
- Массивы C имеют индексацию с нуля: от 0 до n-1.
- Указатели: dereference p[0].
- Арифметика указателей поддерживается.
- Числа Lua автоматически конвертируются в типы C и наоборот.
- 64-битные целые числа поддерживаются через суффиксы LL или ULL (например, 42LL).

Библиотека строкового буфера (string.buffer)

Позволяет высокопроизводительную манипуляцию строковыми данными. Буферы являются изменяемыми последовательностями 8-битных символов.

Использование:
local buffer = require('string.buffer')
local buf = buffer.new()

Методы:
- buf:put(str|num|obj): Добавляет данные в конец буфера.
- buf:get([len]): Извлекает данные из начала буфера.
- buf:reset(): Очищает буфер без освобождения памяти.
- buf:tostring(): Создает строку Lua из содержимого буфера.
- buf:encode(obj) / buffer.decode(str): Высокоскоростная сериализация Lua объектов.

Сериализация:
Поддерживает большинство типов Lua, вложенные структуры и числа FFI. Не поддерживает функции, потоки и userdata. Скорость кодирования может достигать 1 ГБ/сек.

Управление JIT-компилятором (модуль jit)

- jit.on() / jit.off(): Включает или выключает JIT-компиляцию.
- jit.flush(): Очищает кэш скомпилированного кода.
- jit.status(): Возвращает текущий статус компилятора и доступные оптимизации.
- jit.opt.start(level): Установка уровня оптимизации (например, jit.opt.start(2) для -O2).

C API расширения:
luaJIT_setmode(L, idx, mode) позволяет управлять VM из C-кода (включать/выключать функции, сбрасывать трассировки).

Профайлер

Запуск через командную строку:
luajit -jp myapp.lua

Опции:
- f: Стек по именам функций.
- l: Стек по строкам.
- v: Показ состояний VM.
- z: Показ зон (jit.zone).
- i<number>: Интервал выборки в мс (по умолчанию 10мс).

Lua API профайлера:
local profile = require('jit.profile')
profile.start(mode, callback) — Запуск.
profile.stop() — Остановка.
profile.dumpstack([thread,] fmt, depth) — Получение дампа стека.

Состояния VM в профайлере:
- 'N': Нативный (скомпилированный) код.
- 'I': Интерпретируемый код.
- 'C': Код C.
- 'G': Сборщик мусора.
- 'J': JIT-компилятор.
